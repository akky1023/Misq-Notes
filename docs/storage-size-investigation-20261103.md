## 実装で確認した増加要因

1. `MisqArchiveDirectory.delete()`は外部ファイルを消さず、ステージ中の項目だけを除く。上位の`NotebookArchive.publish()`に孤児整理があっても、外部blobの実削除にはつながらない。`organizeViews()`は世代JSONを2つに整理する一方、古いblobを明示的に保持している。
2. `BlockPackedFiles`は同じ1 MiBブロックを再利用するが、未使用ブロックの回収はなく、ブロックの直接削除を拒否する。既存の全量blobは新方式への書き込みだけでは消えない。現本番に`.blocks`はないため、現状の肥大化はこの方式によるものではない。
3. ブロック化しても先頭のコミット領域が保存ごとに変わるため先頭ブロックは変わる。1 MiB以下のノートでは1ブロック全体が変わり得る。圧縮再配置でも位置が変われば多くのブロックが変わる。
4. `SpatialNoteCache.publish()`は筆跡本文を位置別packに再保存する。過去のindexとpackを回収する処理はない。再生成可能なデータだが、現行packは初期表示を速める役割を持つ。現本番にはまだ存在しない。
5. `MisqFile.commit()`は毎回、本文レコード表・全イベント・現行manifest・previousManifestなどを末尾へ追記する。サムネイル更新も索引を丸ごと追記する。2領域方式に必要なのは2つの確定状態であり、それ以前の索引本文を無期限に保持する必要はない。
6. `compactIfNeeded()`は存在するが、閾値は概ね「本文全レコード + サムネイル + 索引2個」の3倍に8 MiBを足した値である。呼び出しも`NoteRepository`の削除・置換などに伴う限定回数の整理に結び付いており、追加筆記だけで必ず定期実行される仕組みではない。
7. `NoteRepository.encodeStroke()`は筆跡ごとにブラシ種類・色・太さ・epsilon・筆圧曲線を保存する。点列はAndroidX Inkの`inputs.encode()`で保存し、描画用メッシュや輪郭パスは保存していない。
8. `EditorStroke.translated()`は移動後に新しいstorageIdと全文点列を作る。画像も`ImageRecord.encode()`がPNGを丸ごと埋め込むため、移動・拡縮の履歴ごとに同じPNGを保存し得る。
9. 現行の`placements`は`previous.placements + placements`で追記され、削除・置換済みstorageIdの位置情報も残り得る。現行索引で必要な参照範囲を確認して整理する余地がある。今回の本番11冊と10月28日の標本にはこの項目がなく、容量効果は未計測。

## 削除してはいけないものと保持方式

`.recovery`は単なるバックアップではなく、チェックサム付き確定世代の正本である。現在のノートと同じ内容のblobも、表示用ファイルが途中で壊れた場合に必要になる。

最新2世代から参照されないblobでも、別端末の`.notes-external-state`にあるbaselineがそのハッシュを保持している場合がある。`ExternalWorkingSet.baseBlobs()`から`MisqMerge.mergeFiles()`へ渡され、両端末が変更したノートの基準本文を読み出す。単に「最新2世代以外を消す」変更は、長期間オフラインだった端末の統合を壊す。

未確定の保存、同時書き込みの分岐、競合用の別ノート、読み取り中の参照も保護が必要である。イベントの親ID・対象ID・削除記録は再出現防止と因果関係の判定に使われる。履歴本文やpreviousManifestも現在の復旧・競合処理に使われるので、不要データと扱わない。

## 推奨する着手順

### 古い索引の再配置の実装結果

`MisqFile`の本文保存・変更なしの保存・サムネイル更新に、古い領域の自動整理を追加した。不要領域が8 MiB以上、かつファイルの25%以上なら再配置する。通常の判定はコミット領域のサイズ情報を使い、索引JSONの再エンコードをしない。

再配置では両確定状態のレコードを保持し、元ファイルを1回開いたまま筆跡を順にコピーする。同じプレビュー領域は再利用する。置換前に再配置先の両索引と全履歴本文のハッシュを検証し、失敗時は元ファイルを残す。保存直後の整理に失敗しても、すでに確定した保存は成功として扱う。

取得済み11冊のコピーで、**462,569,198 B → 93,008,313 B（441.14 MiB → 88.70 MiB、79.89%減）**を実測した。小さい1冊に残る3,234,484 Bは8 MiBの整理閾値未満である。現在の47,549件、全63,423件の本文レコード、74,624件のイベントは同数で、両確定状態の管理情報・本文レコードのハッシュ・プレビューハッシュが一致した。元の取得済み11冊はハッシュが変わっていない。

回帰テストは追加筆記だけで整理されること、変更なしの保存とプレビュー更新でも整理されること、削除済み本文と直前プレビューの保持、最新領域の破損時に直前の領域から復旧すること、履歴本文の破損時に元ファイルを置換せず耐久保存を維持することを対象にした。

全体テストは325件中324件成功・1件スキップ（11冊のコピー検証を含む）。その後に追加した変更なし保存・プレビュー更新のテストも含め、最終の`MisqFileTest` 21件は全件成功した。検証APKのビルド成功、release lintはエラー0件・変更箇所以外の警告12件だった。ログは`captures/compaction-validation-20261103.log`と`captures/compaction-final-unit-20261103.log`。

検証出力は`captures/storage-compaction-20261103/`、元コピーは`captures/storage-audit-20261103-current/`。外部に残る旧recoveryコピーのサイズはこの変更だけでは減らない。

ユーザーの許可後、検証版`net.neomenia.misqnotes.probe`と実機テストAPKを更新した。`CompactionIntegrationTest` 2件が成功し、削除済み筆跡の履歴とプレビューの保持、通常保存による自動整理を確認した。取得済み実ノートの私有コピーは111,835,053 Bから6,432,674 Bへ整理され、4,573本文レコード・5,388イベントと両確定状態の管理情報・本文ハッシュが一致し、最初と最後の筆跡を復号できた。この整理処理は858 ms、元コピーのハッシュは不変だった。試験用に端末へ配置したコピーは削除した。

### 残る候補

1. 筆跡のペン設定をノート内の辞書へ共通化する。点列は同じバイト列のまま保持し、旧HNS1を引き続き読める形式にする。索引の圧縮・UUIDのバイナリ化も比較する。全ファイル一括圧縮はランダム読み込みとブロック差分を損なうので避ける。
2. 今回確定した現在の復旧blob参照に加え、利用する各端末のbaselineを確認する。端末ごとの同期確認・基準の固定、または古い基準を失った場合の明示的な復旧方式を設計してから保持期間と回収を実装する。移行時には全量blobを共有ブロックへ置換できるかも検証する。
3. 外部の回収は、保護するblob・確定世代・編集中の参照・保存途中の参照を決め、そこから到達するブロックを残す方式にする。書き込み競合や一覧の不完全取得があれば削除しない。位置別キャッシュも読み取り中の参照を保護してから世代単位で回収する。
4. 画像のPNGと配置を分離し、同じ画像の移動・拡縮で画像本体を共通利用する。筆跡の移動も本文と変換の分離を検討できるが、消しゴム・境界・書き出し・統合への影響を別途検証する。

点列の座標・筆圧・時刻・傾き・方向の省略や間引きは、ブラシの再現性を確認できるまで行わない。今回、その必要性を示す計測結果は得られていない。

## 再計測

読み取り専用の標準Pythonスクリプトを追加した。入力は取得済みの保存先コピーとし、本番端末からの取得や削除はスクリプトに含まれない。

```powershell
python scripts/audit_storage.py captures/crash-recovery-20261028/inkdata > captures/storage-audit-20261103.json
python scripts/audit_storage.py captures/storage-audit-20261103-current/inkdata --recovery-inventory captures/storage-audit-20261103-current/inventory-before.txt > captures/storage-audit-20261103-current/audit.json
```

MISQ0001/0002のノートを解析し、MISQBLK1は管理ファイルとして数えるだけで本文を再構築しない。`--recovery-inventory`は取得済みの`ls -ln`一覧からblobの名前とサイズを照合する機能であり、blob本文を検証する機能ではない。`directories`の集計対象はローカルコピーだけである。JSONの圧縮値は実験値、両コミット領域外のサイズは参照範囲の計測値であり、削除コマンドや削除可能なファイル一覧は生成しない。
