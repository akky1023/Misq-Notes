# Notewiseの筆記時温度測定（2026-11-07）

Notewise 3.6.4（`com.yygg.note.app`）で12分間の連続筆記を1回行った。

## 結果

| 指標 | Notewise | 前回のMisq軽量描画版（参考） |
|---|---:|---:|
| バッテリー温度 | 25→25℃ | 25→30℃ |
| 終盤CPU温度平均 | 34.4℃ | 69.1℃ |
| 終盤GPU温度平均 | 32.1℃ | 64.9℃ |
| 開始CPU温度 | 31.3℃ | 30.1℃ |
| 開始GPU温度 | 30.1℃ | 28.9℃ |
| 最大thermal status | 0 | 0 |

Notewiseの完了ログ: `EXTERNAL END cycles=1111 seed=480`。入力が受理されたことに加え、準備後・途中・終了後の画面で実際の筆跡の増加を確認した。ストローク数は入力送信数であり、Notewiseの内部保存データを直接数えた値ではない。

## 方法と比較上の制限

- 同じXiaomi Pad 7（Android 16）、横向き3200×2136、輝度設定71・自動輝度オフ、USB接続。開始時の表示モードは60Hz。
- 既存ノートに触れず、新規ノート `Thermal-test-20261107` を作成した。選択済みの黒ペンと薄茶色の用紙を使用し、ツール設定は変更していない。
- ページ内に筆記領域が収まるよう、準備時に表示倍率を427%へ合わせた。計測中は筆記だけを行い、ズーム・スクロールはしていない。
- 前回Misqの3,600本の初期筆跡を直接移せないため、表示中の本数の目安として480本を別途準備した。ノート全体の筆跡数・形状・色・ペン幅・描画面積・保存方式は同一ではない。
- 一時的なAndroid計装テストからUiAutomation経由でSTYLUS MotionEventを送り、長さ・向き・曲率・位置・筆圧を変えた。筆記の乱数列はMisqの初期筆跡作成後と同じ位置に進め、ストローク150〜650ms・入力間隔約8ms・休止100〜350msとした。横方向の基準はMisqの3200pxに対して2100pxで、線の画面上の長さと領域も異なる。
- 前回MisqはViewへ直接イベントを配送し、今回はOSの入力経路を通る。物理ペンとデジタイザによる入力ではない。厳密な同条件のアプリ性能比較や消費電力の測定にはならない。
- 準備後は画面を点けたまま温度を安定させ、15秒間隔でバッテリーとthermal HALの現在温度を記録した。終盤平均は最後3分。CPU/GPUは各時点の最高温度センサーで、CPU使用率ではない。NotewiseのプロセスCPUカウンターは採取していない。
- 温度差だけではNotewise内部の描画方式や、Misqの発熱原因を確定できない。既存筆跡の再描画頻度・キャッシュ・保存時のプレビュー生成は、Misq側で別途検証すべき候補として残る。

## 記録と後片付け
