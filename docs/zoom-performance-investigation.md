# 拡大・縮小時のカクつき調査（2026-11-03）

## 原因と修正

`StrokeRenderCache.draw` は倍率が変わるたびに全RenderNodeを破棄していたため、ピンチ操作中に表示中の全筆跡をUIスレッドで再記録していた。Inkのローカル座標化キャッシュは128画までなので、大量の筆跡の再記録では形状の再生成も繰り返される。

倍率変更による全破棄を削除し、パン・ビュー幅変更ですでに使用していた変換をズームにも適用した。記録時と現在のスケールの比、および表示原点の差でRenderNodeを変換する。各ノードが異なる倍率で作られた追記部分にも適用される。

RenderNodeはビットマップではなく描画命令を保持する。現在のInk描画はパス方式で、対象API 29以上ではパスとCanvasが筆跡座標を使うため、記録済みパスを現在の倍率で描画できる。筆跡の変更、消去、選択変更、表示対象の変化による必要な再記録は維持する。
