# 検証JSONと筆跡データの容量

検証JSONは筆跡の保存形式ではありません。MotionEvent/KeyEvent、ホバー、端末情報、各イベントのhistory、読みやすいフィールド名・改行・インデントを保持します。

実際のノートでは、入力点と筆跡ごとのペン設定を中心に保存します。座標・時刻・筆圧・傾きなどの値を毎点の名前付きオブジェクトではなく点列として保持し、ホバー・指・キーの生ログを含めないことで容量を削減できます。描画用メッシュは再生成可能なため、必須保存項目とはしません。

| 元のログ | 検証JSON | 筆跡点のみのコンパクトJSON | 左記をgzip圧縮 |
| --- | ---: | ---: | ---: |
| 下.json | 1,021,807 bytes | 148,727 bytes | 22,563 bytes |
| 上.json | 913,153 bytes | 112,470 bytes | 16,562 bytes |
| 独立.json | 1,024,200 bytes | 111,807 bytes | 16,568 bytes |

比較データには、完了したSTYLUS/ERASERの接触ごとに、時刻・X・Y・筆圧・傾き・向きを配列で収録しました。history内の点も保持し、点の間引きは行っていません。筆跡点数は順に1,617点・1,222点・1,208点です。ペン設定とIDは比較用に付与しました。元ログの座標系のままなので、編集画面のノートファイルではありません。

この表はPhase 2時点の試算で、最終保存形式や今後すべてのノートでの圧縮率を保証する値ではありません。現在の本番用MVPには、以下の形式で自動保存を実装しています。

## 本番用MVPの保存形式

Jetpack Inkのstorageモジュールは、入力点を圧縮されたProtocol Buffers形式で扱います。[公式モジュール資料](https://developer.android.com/develop/ui/views/touch-and-input/stylus-input/ink-api-modules)を参照してください。バージョン1.0.0の`StrokeInputBatch.encode/decode`にはgzip処理も含まれています。

本番用MVPでは、この入力点形式と筆跡ごとのID・ブラシ情報・ノート形式のバージョンを組み合わせた方式を採用しました。[保存形式の詳細](storage-format.md)を参照してください。encode/decode、筆跡の再構築、ノートの再読込の実機テストソースも用意しています。実機での実ファイル容量・長時間筆記の性能は今後確認します。
