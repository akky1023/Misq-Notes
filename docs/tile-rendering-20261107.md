# 完成済み筆跡の画像タイル化（2026-11-07）

## 実装

- 前回の描画精度を下げる変更を破棄した。通常描画の許容誤差 `min(0.01, ペン幅/128)`、筆圧補正、保存入力と元のエクスポート経路を維持した。
- 完成済み筆跡を画面解像度の256pxタイルに保持し、筆記中の1本は既存の独立したInk入力層で描く。
- タイルは専用の直列バックグラウンド処理で作り、未完成の領域だけ従来のベクトル描画で補う。準備中も空白や消去前の筆跡を表示しない。
- 線が末尾に追加される場合は該当タイルの既存画像へ追加分だけ描く。消去・Undo・選択移動・画像拡大縮小では変更した範囲を作り直し、筆跡と画像の重なり順・透明度を保持する。
- ズーム中は既存タイルを変形して使い、終了後150ms以上倍率が安定したところで新しい解像度へ切り替える。パンで入ってきた領域だけ作成する。メモリー上限を超えそうな場合は操作中でも解像度を調整する。
- 画像キャッシュは最大80MiBまたはVM上限の3分の1の小さい方。LRUで古いタイルを除去する。メモリーが少ない端末では表示用タイルの解像度を下げ、割り当てに失敗した場合は従来描画へ戻す。これはタイル画像の予算であり、アプリ全体やGPUメモリーの上限ではない。
- Viewが破棄されたときは処理をキャンセルし、古い非同期結果が新しい画面や編集状態に戻らないようにする。RenderThreadが参照中のBitmapを手動でrecycleしない。
- サムネイル用SaveQueueのみ、更新要求が1秒途切れるまで最新スナップショットにまとめる。本体保存の500msの固定ウィンドウ、実行中の書き込み、明示的なflushは維持した。外部保存前のflushでは必要なプレビューを待つ既存動作が残る。
