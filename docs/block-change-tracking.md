# 位置別ブロックの変更記録（2026-11-03、検証版）

高さ1000論理ピクセルの帯ごとに内容の署名と未保存の変更世代を記録する。
追加・削除は対象の帯を、帯をまたぐ移動は移動元と移動先の両方を変更扱いにする。
署名には描画順ID、本文UUID、本文SHA-256、開始位置・上下端を使う。
ノート名・用紙・表示位置などのノート情報は、本文の帯とは別の署名と変更世代で記録する。
サムネイル更新は本文の帯を変更扱いにせず、ファイルの保存世代だけを進める。

## 内部の記録

`notes/.block-state/<ノートUUID>` にチェックサム付きで保存する。
各帯の現行署名、未保存世代、ノート情報の署名・未保存世代、最後に確定した本文ハッシュ、確定済み世代、ファイルの識別情報・高精度更新時刻・サイズを持つ。
記録がない・壊れている場合は本文から再構築し、変更ありとして保守的に処理する。
ノートの削除時は、そのノートの変更記録とバックアップだけを除去する。

スナップショットは作成時点の変更記録を固定して持つ。
外部の確定と位置別データの公開が成功した後、そのスナップショットの世代までを保存済みにする。
保存中に再編集した帯やノート情報の未保存世代は残す。
新しい世代が確定済みの場合、遅れて届いた古い完了通知では保存基準を戻さない。
保存に失敗した場合は未保存記録を維持する。

位置情報が未整備の場合は専用の未分類帯へまとめ、位置別データの省略判定には使わない。

## 再利用する処理

- 最後に確定した位置別索引と、変更なしの帯の構成が一致すれば、その帯の不変パックを再利用する。再起動後も未変更帯の本文を再度ハッシュ計算しない。
- パックの読み込み時は従来どおり各筆跡とパック全体のSHA-256を検証する。
- 保存済み本文と同じファイル識別子・更新時刻・サイズで、変更記録も保存済みなら、次の同期では本文をコピーせず確定済みの参照を使う。
- この本文ファイルの再利用確認はストレージインスタンス内だけで保持する。再起動、ファイル置換、変更記録の欠落・破損などでは保守的な全文処理へ戻る。
- 外部のオブジェクトが消えていても、内部本文がスナップショット作成時から変わっていなければ、内部から検証用コピーを作って修復する。作成後に内部本文も変わっていれば修復を中止し、未保存データを保持する。

## 残る処理

ノート本文やノート情報が変わる保存では、全文MISQ0002への確定と全文スナップショット処理が残る。
今回の変更は、変更帯の耐久記録・世代ごとの確認・未変更データの再利用まで。
保存を位置別ブロックだけで確定する方式、外部保存完了を待たずに一覧へ戻る動作は別の段階とする。
recoveryと未使用ブロックの整理・軽量化は行わない。
