# 大量筆記ノートの調査と軽量化（2026-10-16）

## 提供データ

`Note.zip` は読み取り専用で調べ、アプリのソースやAPKへ同梱していません。

| 項目 | 結果 |
| --- | ---: |
| ZIPサイズ | 1,650,588 bytes |
| 最新ノートの筆跡 | 1,093画 |
| blob | 2,054個、合計923,262 bytes |
| 保存世代 | 2世代（542、543） |
| 両世代から参照されていないblob | 366個 |
| SHA-256不一致 | 0個 |

データの破損やblobの総容量だけでは停止を説明できません。コードでは次の増幅要因を確認しました。実機の停止原因をプロファイラーで特定した結果ではありません。

- 外部保存1回にフォルダ全件取得を3回実行し、新しいblobを書き込む際にも保存先フォルダを再取得していました。
- 1画の完了ごとに保存し、サムネイルの描画器も毎回作り直すため、既存筆跡の輪郭キャッシュを再利用できませんでした。
- ペンボタンの状態変更や、消しゴムが何にも当たらない入力でも、表示中の全筆跡を再描画していました。
- ローカルの不要筆跡整理は開いた時だけだったため、開いたまま編集を続けると保存対象ファイルが増えました。
- 起動時と保存先指定時は、完全性確認のために全blobを読み、取り込みでも同じblobをもう一度読んだ後、外部への保存まで待っていました。ユーザーの実機では起動・保存先指定から表示まで約20秒かかり、開いて閉じる際にも待ちが発生しました。

## 修正

- 外部保存の全件取得を1回に統合し、同じ保存処理内の書き込みと旧形式の移行で取得結果を再利用します。次の保存では再取得し、失敗後の再試行でも実際のファイルを確認します。
- SHA-256の16進表現を直接生成し、大量の文字列フォーマッター生成を省きます。ハッシュと保存形式は変更しません。
- ノートの端末内保存は500ミリ秒の固定窓で最新スナップショットへ集約します。継続筆記でも無期限に先延ばしせず、進行中の書き込みを中断しません。画面を閉じる処理は端末内への保存を待ち、外部同期を待ちません。ファイル処理はIOスレッドで行います。
- 位置や設定だけが変わった保存では、変更のない筆跡スナップショットを再利用します。
- サムネイルの描画器を再利用し、一覧の非同期プレビュー要求で生成します。開く・閉じる・保存する処理はサムネイル生成を待ちません。直近のノートは復元済み筆跡も再利用します。
- 通常の画面描画を安定した編集IDの64枠ごとのRenderNodeに分け、変更のない描画命令を再利用します。追加・削除・Undo・選択移動では該当する群を更新し、倍率・画面サイズの変更では作り直します。平行移動では記録時の位置との差分で描画命令を再利用し、画面端をまたぐ筆跡もクリップせず保持します。画面を閉じると解放します。
- 内容・用紙・表示位置・選択が変わらない状態通知では筆跡層を再描画しません。
- 保存時にも不要なローカル筆跡を整理し、最新と直前の管理情報が参照する筆跡は残します。Undoで再び必要になった筆跡はメモリ内の入力データから再保存します。
- 0.1.1では、検証済みblobを上限8MiBのキャッシュで取り込みにも使い、初回読み込みの重複をなくしました。小さい外部ファイルは最大4本で並列読み込みし、大きいファイルやサイズ不明のファイルは逐次読み込みします。
- 再起動時は端末内のコピーを保存世代のハッシュと照合し、一致するファイルの外部読み取りと再取り込みを省きます。不足・破損があれば外部の正常な内容で復元します。起動直後の不要な外部への書き戻しも省きました。
- 外部への同期は別キューで750ミリ秒単位に集約し、変更されないバイト列のスナップショットから行います。外部IO中はローカルの編集用ロックを保持しません。同期中の追記は次のスナップショットへ含め、古い同期成功で新しい変更の未同期マーカーを消しません。
- 未同期マーカーはローカル編集前に書き込み・同期します。外部保存の失敗・アプリ終了時にもローカルコピーを残し、次回起動時は外部の古い状態で上書きせず、バックグラウンドで再同期します。同期の失敗は既存のエラー通知と再試行操作で扱います。

## 検証

単体テスト169件成功（失敗・スキップ0件）。提供ZIPを使うテストは環境変数`MISQ_PERF_ZIP`を設定した時だけ実行し、内容を公開しません。最新ノートの復元、管理情報の一致、不要blob整理、2世代保持、整理後の再復元を確認しました。保存キューの集約・継続入力・待機・失敗再試行、破損時の前世代復旧も検証しています。

外部の全件取得回数は同じデータで3回から1回になりました。Windows上の実ファイルとメモリ内の外部保存先を使った参考計測では、初回保存は変更前5,949ms、変更後3,839ms、変更後の既存筆跡のハッシュがキャッシュされた保存は3回平均141msでした。ファイルキャッシュやウイルス対策ソフトの影響を受ける単発値で、Androidの外部保存速度や操作時のフレームレートを表す値ではありません。

0.1.1の追加検証では、初回の外部blob読み取りが検証・取り込み合計3,374回から1,687回になりました。ローカルのコピーが一致する再起動では外部blob読み取り0回を確認しました（外部の世代情報とファイル一覧は取得します）。PC上の再起動時の照合は参考値264msでした。実機での所要時間を保証する計測ではありません。

外部保存をラッチで停止させるテストで、その間のローカル編集が完了すること、新しい変更の未同期マーカーを古い同期完了が消さないこと、最新の内容が後続の同期で復元できることを確認しました。外部保存失敗時のローカル内容・未同期マーカー保持と再試行成功、スナップショット取得後にローカルファイルを変更・削除しても同期内容が変わらないことも検証しています。

Debug/Release APKの作成、Debug Lint（エラー0、警告10）、Androidテストのコンパイルに成功しました。追加した実機テストは、1,093画から1画増減した時の再記録が該当群の最大64画に収まること、順序・選択移動・倍率変更、保存中の不要筆跡整理とUndoによる再保存を対象にしています。

接続端末・エミュレーターがないため、Androidテストの実行、GPU上の見た目・操作感、外部ストレージの実速度は未確認です。実機では提供ノートを開き、追記、消去、Undo/Redo、投げ縄移動、ズーム・スクロール、一覧への復帰と再起動後の復元を確認する必要があります。


## スクロールと筆跡キャッシュ（2026-10-20）

- 総合設定 → ノート設定で、高精度な輪郭の保持量を128本・画面内すべて・前後1画面を含む3画面・ノート全体の4段階から選べます。既存設定の移行時も標準は前後1画面です。
- 128本モードでは保持対象を先に選び、それ以外の描画で保持対象を追い出しません。画面内モード以上では可視本数による128本の追い出しを行いません。
- 画面外の輪郭は300msの待機後にワーカースレッドで順次生成し、ペン・指の操作中は次の生成を待機します。古い先読みが保持範囲の変更や画面を閉じた後にキャッシュを復活させないようにしています。
- 画面外へ出た描画命令も保持範囲にある間は再利用します。追加した末尾の記録位置は個別に保持し、スクロール後の追加・まとめ直しでも位置を合わせます。


実機Xiaomi Pad（2410CRP4CG / Android 16）・本番0.1.2で同じノートを同じ指スワイプ4回、約8秒計測した結果、UIの描画命令生成のp95は140.77msから4.50ms、最大は158.79msから6.58ms、20ms超は28件から0件になりました。OSの60Hz上限は変更しておらず、前後ともThermal Statusは0です。停止中の描画も含むため、この分布をそのままスクロール中のfpsへ換算しません。単体177件・実機10件が成功し、GPU読出しによる画面端の欠けとスクロール後の追加描画位置も検証しました。本番ノートでは指による移動だけを行い、筆跡の追加・消去・選択編集は行っていません。
