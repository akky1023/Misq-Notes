# 筆記中の短い停止と長いノートの軽量化（2026-10-19、0.1.2）

## 結果

筆記の完了ごとに画面スレッドで全筆跡をコピーしていた処理をなくしました。保存キューへ渡す筆跡一覧は不変AVL木の参照として取得し、変更された経路だけを共有・更新します。1画追加の編集はO(log N)、保存用一覧の取得はO(1)です。描画順・1操作単位のUndo/Redo・遅延したInkの完了順を維持します。

保存ファイルの筆跡参照一覧を作るO(N)の処理は、保存キューで集約した後、IOスレッドで実行します。編集を続けても、進行中の保存が参照する筆跡は変わりません。既存のノート形式は変更しません。

## 負荷を減らした箇所

- 追記時の全筆跡コピー・参照一覧生成・大量の一時オブジェクト生成を画面スレッドから取り除きました。
- 少数の選択筆跡の移動・削除では、選択IDから検索し、文書全体の走査を省きました。
- 通常の追記では、64枠ごとの既存描画キャッシュを保ち、追記部分だけを最大8画ずつ更新します。消去・選択移動・表示範囲や倍率変更では必要なキャッシュを作り直します。
- 最後の変更から500ms以上経ち、ペン・指の操作やInk完了待ちがないときに、追記部分を大きなキャッシュへ戻します。1フレームに整理する群は1つです。表示外のキャッシュと画面終了時のキャッシュは解放します。
- 保存時は検証済みの筆跡UUIDをノートごとに保持し、変化しない筆跡について毎回File生成・UUID解析・ノートIDと筆跡IDの連結をしません。
- 不要な筆跡ファイルの全走査は、読み込み後と削除・移動で不要データが発生した世代だけに限定します。最新と直前の保存世代を残し、古い世代から参照が外れる次の保存でも整理します。通常の追記で毎回全ディレクトリを走査しません。

## 実機での比較

接続されたXiaomi Pad 7（2410CRP4CG）のMisq notes検証版だけを使用しました。ADB操作は事前に報告し、他アプリは操作していません。本番版0.1.1のノートを変更したり、本番版を更新したりしていません。比較用データは架空データで、表示テストはノートを読み込まない検証用Activityで行いました。

同じプロセス内で旧方式と新方式を比較しました。各条件40サンプルの95パーセンタイルです。以下の「保存準備」はデータ構造の編集・保存用一覧取得だけで、ディスク保存や実際のペン先から画面までの全遅延ではありません。旧方式はTreeMapの全Entryコピーと参照列生成、新方式は不変木への追加と参照取得です。

| 総筆跡数 | 旧方式の保存準備 | 新方式の保存準備 |
| --- | ---: | ---: |
| 1,000 | 1.656ms | 0.097ms |
| 10,000 | 1.272ms | 0.120ms |
| 100,000 | 29.937ms | 0.690ms |

1万画のうち表示範囲だけを描画する追記テストでは、描画命令の再記録の95パーセンタイルが旧方式1.653ms、新方式0.568msでした。通常の1画追記で更新する範囲が最大8画以内であることと、表示外の筆跡が描画候補から除外されることも検証しました。

実際のInkCanvasViewを表示して24回追記する計測では、フレーム全体の95パーセンタイルは旧58.840ms、新60.818msで、全体の改善は確認できませんでした。最大値は旧104.990ms、新74.859msでしたが、少数サンプルの単発値であり改善保証には使えません。GPU・Inkの入力層・OSの描画待ちなど、今回のCPU処理削減だけでは解決していない負荷があります。

全筆跡を一律8枠で区切る案も比較しましたが、画面全体の時間は改善しませんでした。最終実装は既存部分の大きなキャッシュを維持し、追記部分だけを小さく更新します。

計測時のPowerManagerのthermalStatusは0でした。高温・熱制限の再現試験、電力測定、実際のFocus Penによる連続筆記の入力遅延計測は実施していません。発熱の低減や数十〜数百msの停止解消を確認した結果ではありません。
