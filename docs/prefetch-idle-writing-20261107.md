# 操作中・操作直後の先読み抑制と筆記比較（2026-11-07）

## 実装

- キャンバスでペン・指が接触している間と、最後の操作・編集から1秒間は、画面外の描画準備とノートデータの先読みを待機する。静止したままの接触も対象とする。
- 必要な表示範囲の読み込みは続ける。通常含める上下500の余白は操作中・操作直後には読み込まず、休止後の先読みへ回す。
- 先読みデータの読み込み中に操作が始まった場合は、チェックポイントで中断し、休止後に再試行する。表示に必要な読み込みはこの理由で止めない。すでに実行中のnative処理は安全な区切りまで完了する。
- 読み込みによる筆跡の追加自体は操作とみなさず、先読みが自分の待機時間を延ばし続けないようにする。保存・入力・描画方式は変更しない。

## 筆記のみの比較

同じ実機で旧版→修正版→修正版→旧版の順に、各12分・各2回を測定した。全試行の実際の開始バッテリー温度を以下に示す。

| 版 | バッテリー温度（各試行） | アプリ平均CPU使用量 | CPU内部温度・終盤平均 | GPU内部温度・終盤平均 |
| --- | --- | ---: | ---: | ---: |
| 旧版 | 25→30℃ / 25→30℃ | 152.9% | 79.0℃ | 67.9℃ |
| 修正版 | 25→31℃ / 25→31℃ | 153.0% | 79.4℃ | 67.9℃ |

CPU使用量の100%は1コアを使い切る量。温度は各取得時のCPU/GPUセンサー最大値について終盤3分を平均し、さらに2試行を平均した。筐体表面温度・消費電力の測定ではない。

今回の固定画面・読み込み済みノートでの筆記条件では、発熱低減を確認できなかった。平均CPU使用量とGPU内部温度は旧版・修正版でほぼ同じだった。バッテリー終了温度は修正版が1℃高かったが、各版2試行・温度1℃刻みの比較のため、小さな差の原因は分離していない。先読みを停止・待機・再開する機能自体は実機の筆記テストで確認できた。

## 条件と限界

- Xiaomi Pad 7（2410CRP4CG、Android 16 / API 36）、検証版net.neomenia.misqnotes.probe、USB給電、手動輝度の設定値71。表示モードは1分間隔の別ログに保存した。
- 前日の開始温度27℃とは環境が異なったため、前日の数値だけとの比較は避け、同じ日の旧版を対照にした。準備待機中にバッテリー温度が23→25℃へ変化したため、今回の本測定は25℃を基準に開始条件をそろえた。予備待機・ビルド・修正版本測定前の余白読み込み調整は、操作中の集計に含めない。
- 専用の架空ノートに3,600画を用意し、各回に新規ノートを使った。長さ・方向・曲がり方・筆圧・接触時間・ペンを上げる間隔を変える前回と同じ乱数種のMotionEvent列をInkCanvasViewへ渡した。完成済みの同一Strokeを繰り返し追加する方法は使わない。
- 通常の編集UI、Ink入力、ローカルFormat 3保存、サムネイル更新を通した。筆記中は表示位置を固定し、新しい線を追記した。
- 全試行で冷却と画面点灯後30秒の待機を挟んだ。バッテリー温度は1℃刻みで、室温・筐体表面温度は未測定。各版2試行の比較なので、小さな差を統計的な改善・悪化とは断定しない。
- 初期の周辺先読みを準備中に済ませやすく、筆記中に表示位置を変えない条件である。そのため、今回抑制した処理の出番が少ないと考えられる。今回の結果を、画面移動を伴う使い方や部分読み込み中へそのまま一般化しない。
- 実機の温度試験は筆記のみ。ズーム・スクロールの温度試験は行っていない。物理ペンの通信・OSの入力配信経路・外部同期も比較の対象外。
