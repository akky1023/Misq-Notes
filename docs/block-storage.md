# 外部ノートのブロック保存（2026-11-03、検証版）

後続の変更で、読み込みは[位置別ブロックの遅延読み込み](spatial-loading.md)を追加した。以下は全文保存の転送層の説明。

## 動作

外部保存するノートを1 MiBのブロックへ分け、SHA-256が同じブロックを共有する。
筆跡の座標・入力点・描画順や既存のMISQ0002の内容は変更しない。
保存するのは変更・追加されたブロックと小さな管理ファイルだけで、毎回ノート全体を2か所へ転送する処理を避ける。

高さや筆跡の開始位置では区切らない。既存のMISQ0002は本文を追記する形式なので、バイト位置で固定長に分けることで未変更の範囲をそのまま再利用できる。
境界をまたぐ筆跡・画像も元のバイト列へ完全復元するため、線の切断、座標の丸め、二重登録は発生しない。
物理的な保存ブロックの境界は筆跡レコードの途中にも置かれる。

内部保存、内部作業ファイル、競合統合は従来の自己完結したMISQ0002を使う。
外部から読み込む際は、ブロックを順に読み、1冊のMISQ0002へ復元してから従来の処理へ渡す。
この転送層だけでは座標ごとの遅延読み込みにはならない。現在は別途 `.regions` の位置別データから初期範囲を読み、必要な範囲を追加取得する。

## 外部の配置

```text
inkdata/
  library.json
  <UUID>.misq                MISQBLK1の小さな管理ファイル、または従来の単独ノート
  .blocks/
    block-<SHA-256>           1 MiB以下の不変ブロック
  .recovery/
    revision-....json         確定世代（従来どおり）
    blob-<ノート全文SHA-256>   新方式はブロック管理ファイル、既存データは従来の全量コピー
    blob-...                 フォルダ・プリセットなどの従来のメタデータ
```

外部の新しい `.misq` は `.blocks` を参照するため、そのファイル1個だけではノートを復元できない。
外部フォルダをコピー・同期・バックアップする際は、隠しディレクトリを含む `inkdata` 一式を扱う。
内部へ復元した `.misq` は従来どおり単独で読める。外部のブロック形式を旧バージョンのアプリで読むことはできない。

## 確定と検証

1. 内部の不変スナップショットを読み、ノート全文と各ブロックのSHA-256を計算する。
2. 既存の検証済みブロックを再利用し、未検証の既存ブロックは内容を検証する。欠落・破損した同一ハッシュのブロックは正しい内容で修復する。
3. 新しいブロックは外部への書き込み後に読み戻して、サイズとSHA-256を検証する。
4. 全ブロックが揃った後でノートの管理ファイルを書き、読み戻しで完全一致を確認する。
5. 従来の世代競合チェックを経て確定世代を公開し、可視 `.misq` の管理ファイルを更新・読み戻し確認する。

管理ファイルは `MISQBLK1`、本文長、本文、本文のSHA-256で構成する。
本文はビッグエンディアンのバージョン1、ノート全文のSHA-256、全文サイズ、ノートID、最新索引のSHA-256、ブロック数、各ブロックのSHA-256とサイズ。
一覧・競合コピーの確認はノートIDと索引ハッシュを利用し、通常の確認で全文を展開しない。
任意の名前でコピーされたブロック管理ファイルも、必要時に本文へ復元して既存の競合処理へ渡す。

読み込みは各ブロックのサイズ・SHA-256と、連結後のノート全文のサイズ・SHA-256を検証する。
ブロックの並べ替えなど、個々のブロックは正しくても全文が異なる状態を拒否する。
ブロック読み込みの割り当ては最大1 MiB、管理ファイルの本文は最大16 MiB、ブロック数は最大100,000とし、不正なサイズ指定を拒否する。

検証結果のキャッシュはストレージインスタンス内だけで保持する。
再起動後に未検証のブロックを再利用する場合は、変更のないブロックでも一度読み取り検証が必要になる。

## 移行と保持

既存の全量 `.misq` と復旧blobはそのまま読める。
本文を変更しないノートを一括で変換せず、次に新しい内容を保存する際にブロック化する。
そのノートの初回ブロック保存では全文をブロックとして保存する必要があり、差分転送の効果はそれ以後の保存で得られる。

既存の復旧blobは変換・削除せず保持する。新しい保存世代はブロック管理ファイルから元の全文を復元できる。
ブロック方式と従来方式の世代が混在しても、破損した最新世代から従来の正常な世代へ戻れる。
ノート削除後や中断した保存で残ったブロックの整理は行わない。recoveryの軽量化、保持世代やガベージコレクションは別変更とする。

### 実ノートの読み取り専用コピーによる比較

`BlockStoragePerformanceTest` に読み取り対象のtree URIとノートIDを引数で与え、実際のノートを私有キャッシュへ複製した。
すべての編集・書き込みは専用DocumentsProviderの使い捨て保存先で行い、元のノートには書き込まない。
初回保存後、同じ内容のコピーにタイトル変更を行って保存した各1回の参考値。
初回のブロック化にかかる時間は含めず、変更後の保存ではローカルのタイトル変更・スナップショット作成も計測範囲に含める。

対象は8,157筆跡、変更保存後72,332,113 bytes。復元した本文の全文SHA-256一致と全筆跡レコードの検証も成功した。

| 方式 | 保存時間 | プロバイダー読み取り | プロバイダー書き込み |
| --- | ---: | ---: | ---: |
| 全量保存 | 1,411 ms | 212,108,552 bytes | 144,665,087 bytes |
| ブロック保存 | 1,055 ms | 6,301,393 bytes | 6,282,806 bytes |

この比較では書き込み量は約95.7%、保存時間は約25.2%減少した。
同じ端末・使い捨てDocumentsProviderでの各1回の比較であり、ユーザーの保存先での操作時間や継続的な性能を保証する値ではない。
実ノートコピーの比較テストも1件成功し、今回実行した実機テストは計13件。

## 残る処理

内部の全文スナップショット作成とハッシュ計算、大きな索引の生成・保存は残る。
位置別索引がない場合や内部の未確定作業ファイルを優先する場合は、全文を復元して全筆跡をデコードする。
ローカル処理が支配的なノートでは、転送量の削減ほど待ち時間は短くならない。
