# 頻繁なノートの開閉に合わせた保存・読み込み方針

作成日：2026-11-04。ノートを短時間で開く・閉じる・切り替える用途を優先するための設計案。ここに記載する新方式は未実装であり、既存の保存形式を直ちに置き換える仕様ではない。

## 目的

ノートを開いてから長時間使い続けることを前提にせず、必要な内容を素早く表示し、編集し、別のノートへ移れるようにする。

保存・開く速度の問題から見直した1ノート1ファイルの方式へは戻さず、**開閉のたびにノート全体を処理しない構造**を目指す。本文の重複を減らし、保存中断や同期競合から変更を保護する仕組みも組み合わせる。

## 基本方針

本文を表示範囲に近い適度なまとまりへ分け、位置別読み込み・通常保存・同期が同じ本文を参照する。位置別読み込みのために、本文を別の場所へもう一式保存する構成を減らす。

インデックスは、必要な本文だけを独立して読める保存構造と組み合わせる。巨大なファイル内の位置が分かっても、取得や復元に全文が必要なら開く時間は短くならない。インデックス自体も巨大な全筆跡一覧を毎回読む構成を避け、表示範囲に必要な部分だけを取得できる形を検討する。

自己完結した単体の`.misq`は、書き出し時に組み立てる。日常の開閉・編集のたびに単体ファイル全体を再構築する必要をなくす。

## 操作ごとの処理

| 操作 | 画面の操作を進める前に行う処理 | 後から行う処理 |
| --- | --- | --- |
| 開く | ノート情報、表示位置、必要な位置索引、表示範囲付近の本文を読む | 周辺範囲の必要な先読み |
| スクロール | 移動先の本文を追加で読む | 移動方向に応じた近傍の先読み |
| 書く・消す | 変更した筆跡と操作記録を端末内へ耐久保存する | 変更分の外部保存、プレビュー更新 |
| 閉じる・切り替える | 端末内への耐久保存を確認する | 外部保存を継続し、不要な読み込みを中断する |
| 外部保存 | 変更分と必要な参照を保存・確認し、その後に新しい確定状態を公開する | 不要データの整理、必要な再配置 |
| 書き出し・全体処理 | 対象の処理に必要な本文を取得する | 大きな処理は進捗を示し、中断できるようにする |

表示範囲の本文がまだ揃わない間は、その範囲を空とみなして編集・保存しない。プレビューを先に表示する場合も、実際の筆跡を編集できる状態とは区別する。

## 読み込みの優先順位

1. 前回の表示位置など、今画面に出す範囲を最優先する。
2. 表示範囲の前後を、操作を妨げない範囲で先読みする。
3. スクロールしたら移動先を優先し、不要になった先読みを止める。
4. ノートを閉じる・切り替える際は、そのノートの不要な読み込みと形状生成を止める。

現在の[位置別読み込み](spatial-loading.md)には、初期範囲の表示後に残り全体をバックグラウンドで取得する処理がある。短時間で切り替える用途では、開くたびの全文取得につながるため、通常の先読みは周辺範囲へ絞る。

よく切り替えるノートの索引や表示範囲は、容量上限のあるキャッシュへ残す。ただし、全ノートをメモリへ常駐させる前提にはしない。本文の復号と筆跡の形状生成を分けて測り、必要な範囲だけ形状を生成する。

## 保存と閉じる処理

変更は端末内の小さな耐久ログ等へ保存し、外部への転送は変更分をまとめて行う。保存する本文の単位とファイル操作回数を両方考慮し、細かすぎるファイル分割を避ける。

ノートを閉じる際は、未保存の変更が端末内に残ることを確認できれば次のノートへ進める設計とする。外部保存が完了するまでは、復旧に必要な端末内の作業内容を解放しない。「端末内には保存済み」と「外部への保存も完了」を区別して表示する。

部分読み込みのまま保存する場合も、未読の筆跡への参照を保持する。古い読み込み結果が、編集中に削除・移動した筆跡を復活させたり、切り替え先のノートへ混入したりしないようにする。

## 同期・マージと情報の保護

統合には、AとBの最新ノートに含まれる安定したID、削除記録、変更の関係を使う。自動で判断できない変更は両方を保持し、既存のマージ画面で選べるようにする。古い共通祖先のノート全文を必ず取得することを前提にせず、ノート名・用紙・フォルダ等についても統合に必要な情報を定義する。

本文を複数ファイルへ分けるため、確定情報だけが先に届く状態を扱う必要がある。受信側は必要な本文の未着を空のデータとして保存せず、以前の正常な状態を保持して再試行する。同期ソフトによる1ファイル単位の転送と、アプリが管理する複数ファイルの依存関係を区別する。

送信途中、読み込み中、バックアップ中の本文は整理対象から保護する。端末内の未送信の変更、競合する最新ノート、復旧点に必要な本文も保持する。共有先での物理削除は、これらを保護できる条件が確定するまで有効にしない。

チェックサムで本文の破損を検出し、重要な確定情報を保護する。共有本文が壊れると複数世代に影響するため、独立したバックアップと復元確認も用意する。詳細な制約は[設計レビュー](storage-architecture-review-20261104.md)を参照する。

## 開閉の経路から外したい処理

- ノート全文の取得と、単体`.misq`への復元。
- 全筆跡・全履歴を含む巨大な索引の一括解析と再生成。
- 開くたびの全文ハッシュ計算や、保存先全体のファイル一覧走査。
- 通常表示で使わない筆跡の復号・形状生成。
- 閉じるたびの全文外部転送、重い圧縮、不要データの回収。

完全なデータ検査は必要だが、通常の読み込みでは使う本文を検証し、全体の検査は別のタイミングで行う。検証を省略して速度を得た結果と、処理する範囲を減らして得た結果を区別する。

## 検証する項目

同じ取得済みノートのコピーを使い、現在方式と試作方式を比較する。

- キャッシュがない初回と、再度開く場合それぞれの表示開始・編集可能になるまでの時間。
- 短時間で複数ノートを往復したときの待ち時間、不要な背景読み込み、UI停止。
- 初期表示までに読んだバイト数と、ファイルを開く・一覧を取得する操作回数。
- 本文の復号時間、筆跡の形状生成時間、最大メモリ、キャッシュ容量。
- 追記・削除・移動・ノート切り替え時の端末内保存時間と、外部への書込み量。
- 保存先全体の容量。本文だけでなく索引、変更履歴、復旧点、キャッシュも含める。
- 未着、保存中断、容量不足、ノート切り替え中の中断、同時編集から復旧した際の情報の一致。

まず表示開始までの読取り量・ファイル操作数・復号時間を計測し、開閉の経路に残る全文処理を特定する。パックの大きさやキャッシュ量は、その結果に基づいて決める。
