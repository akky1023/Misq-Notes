# 0.1.3の起動・外部保存と移行

## 起動

端末内に既存ノートがある場合は、端末内の復旧処理と一覧DBの取得を終えた時点で一覧を操作可能にします。外部保存先への接続と整合性確認はその後にバックグラウンドで行います。端末内にまだライブラリがない初回取り込みでは、データ取得を待ちます。

接続が完了する前や接続が失敗した場合も端末内の編集を保存でき、外部保存が必要な変更は `.notes-pending` にファイル同期して記録します。同期はローカルファイルの不変スナップショットを取得してから外部IOへ移り、外部の待ち時間で編集処理のロックを占有しません。古い同期完了は新しい変更の未同期マーカーを消しません。

## 外部の保存形式

```text
ユーザー指定の保存フォルダ/
  packed-v1/
    pack-<SHA-256>
    index-<20桁の世代番号>-<UUID>
  notes/、history/、settings/    移行前の形式を保持
```

`pack-*` は複数の筆跡・管理情報・保存世代をまとめた不変ファイルです。約1MiBを目安に分割し、大きい単一レコードはそのまま単独のパックにします。新しい内容だけを新しいパックに保存します。端末内の筆跡ファイル形式は変更していません。

パックはマジック `HNP2`、形式1、レコード数、名前・長さ・内容の列、本文のSHA-256を持ちます。各blobの内容ハッシュと各保存世代のチェックサムも確認します。インデックスは `HNI1`、形式1、名前→パック名の対応表とSHA-256を持ちます。長さ・件数・名前・重複を検証し、本文上限も設けています。

パックを書いて読み戻しを確認した後、最後にインデックスを書いて読み戻しを確認することで保存世代を確定します。途中で止まったパックは確定済みの一覧へ入りません。インデックスは正常な直近2世代を保持します。最新の破損時は直前の正常なインデックス・保存世代を試します。

不変パックは自動削除しません。他の端末が未確定のインデックスで参照する可能性と、復旧時の資料を残すためです。過去のパックは蓄積するため、将来の整理処理は別途必要です。無関係なユーザーファイルは削除しません。

新形式の起動では `packed-v1` だけを列挙し、移行前の大量の筆跡フォルダを走査しません。旧形式の読み取りも二重列挙をやめました。

## 移行・外部更新・競合

- 新形式がない保存先では旧形式を確認して取り込み、バックグラウンドで新形式を作ります。確定前にも旧形式の保存世代が変わっていないことを確認します。旧形式のファイルは残します。
- 同期時には最後に確認した外部の保存世代と現在の世代を比較し、別の書き手の更新を黙って上書きしません。同時確定で同じ番号のインデックスが分岐した場合も同期を止めて保持します。
- 端末内が最後の同期時点から変わっておらず、外部だけに更新がある場合は、別の領域へダウンロードして通知します。次の起動前に端末内が変わっていないことを再確認して反映します。使用中のノートは差し替えません。
- 両方に変更がある場合は端末内の内容と取得した外部コピーを保持して通知します。現在の端末の内容を別の空の保存先へ保存する操作が可能です。自動マージはしません。
- 外部が破損して古い世代へ復旧した場合は、その状態を区別します。既知の同期済み端末内データがある場合、それを古い外部世代で置換しません。
- 移行後に旧バージョンが旧形式へ書き込んだ更新は、新形式と自動マージされません。同じ保存先を使う端末は0.1.3以降へ揃えてください。

## バックアップ

初回の移行前に、アプリの内部ファイルと設定を `noBackupFilesDir/before-packed-v1.zip` へ保存します。全ファイルのSHA-256マニフェストを含め、ZIPを読み戻して確認し、ファイル同期してから確定します。

今回の更新ではPCにも `captures/production-backup-20261022/` へ外部保存先の全ファイルと更新前APKを退避しました。外部バックアップのSHA-256は `fee6aeae113933e8122962512f60a9dba0b95cf93e9b4c48e4128d865477edda` です。最新世代の7,196ファイルを展開し、4冊・6,868本の筆跡と参照ファイルの一致を確認しました。実データはGit管理対象外です。

内部バックアップをPCへ取得する経路は、既知の署名を持つこの検証アプリへの当該ファイルだけのURI権限付与に限定します。

## 検証

単体テストではパックとインデックスの中断・破損・復旧・再試行・他の書き手との競合、未公開パックや無関係なファイルの保持を確認しています。

実データのコピーを使った実機テストで、接続前の編集、旧形式からの移行、新形式からの復元、再接続、外部更新の取り込み、競合時の両方の保持を確認しました。接続中のローカル編集は26ms、移行後の再接続と整合性確認は1,389msでした。移行直後の保存物は6個です。通常のノート編集・自動保存・一覧・再オープンも成功しました。

生ログは `captures/packed-production-20261022/integration.txt` にあります。
