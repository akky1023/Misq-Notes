# 処理の最適化（2026-11-05）

`develop` の `583a7cc` を基点に `develop-optimization` で実施。
保存形式・筆跡の順序・消しゴムや選択の仕様は変更していない。

## 変更

- 筆跡パックの読み込みをバッファ化し、小さなファイル読み取りを削減した。
- パック全体と各筆跡のハッシュ検証、未表示部分の検証、末尾と切断の検出は維持した。
- 筆跡一覧の添字アクセスをページ末尾位置の二分探索にし、順次走査はページ単位にした。本文の遅延読み込みは維持した。
- 表示候補のバケットに項目を直接保持し、検索ごとの世代番号で重複を除外した。候補集合の確保と繰り返しのID検索を削減した。
- 呼び出し元がない `EditorViewModel.visibleStrokes()` を削除した。

## 実ノートによる比較

ユーザーから使用許可を得た検証版の「解析学基礎2」を使用。
8,157筆、36,703,652 bytes。元の外部フォルダから読み取り専用でコピーし、
テスト専用のディレクトリ内で現行形式へ取り込んだ。元のノートと保存設定は変更していない。

端末モデル `2410CRP4CG`、Android 16、debug APK。同じ端末・テストで、
最適化前の2クラスと最適化後を比較した。各処理を3回ウォームアップ後、9回計測した中央値。
ファイルキャッシュを消すコールド起動の計測ではない。

| 対象 | 変更前 | 変更後 | 所要時間の短縮 |
| --- | ---: | ---: | ---: |
| 初期表示範囲327筆の読み込み・内容検証 | 35.36 ms | 24.61 ms | 30.4% |
| 同範囲の読み込み・Ink筆跡復元 | 128.92 ms | 117.77 ms | 8.6% |
| 実際の筆跡境界を用いた表示候補検索500回 | 292.90 ms | 179.73 ms | 38.6% |

読み込みは毎回新しいストアを使用。候補検索では全筆跡を事前に復元して境界だけを保持し、
実際のアプリと同じく境界がない筆跡を除外した。横幅1,000、縦幅2,000の領域を
ノート全長にわたり移動し、全件走査とID・順序が一致することを確認した。
計測には結果を検証する処理も含む。

原本のSHA-256は前後とも
`227e3a5699732eac9fc2cd7f4918a1e6e4e9d2425f1a54a6144125ef1e5ca09e`。
コピーした本文と計測用の現行形式データはテスト終了時に削除した。

## 合成データによる実機比較

| 対象 | 変更前 | 変更後 | 所要時間の短縮 |
| --- | ---: | ---: | ---: |
| 4,096筆の読み込み・内容検証 | 219.62 ms | 175.49 ms | 20.1% |
| 4,096筆の一覧走査 | 121.92 ms | 120.68 ms | 1.0% |
| 10万筆の表示候補検索500回 | 236.81 ms | 127.50 ms | 46.2% |

一覧走査はこの規模ではメタデータの読込・検証が支配的で、実測の改善は小さい。
二分探索は多数ページへの添字アクセスの計算量を減らす変更として扱う。
上記は対象処理の結果であり、アプリ全体やフレーム時間が同率で短縮することを示さない。
特にInk筆跡の復元を含めると、読み取り以外の処理時間が多く残る。
