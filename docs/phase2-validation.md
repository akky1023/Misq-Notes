# Phase 2 描画・消しゴム・Undo/Redo

実装バージョン：0.2.0-phase2 / applicationId：net.neomenia.handwriting.probe。

これは保存前の描画検証アプリです。プロセス終了後の筆跡復元は未実装です。入力検証画面は「設定 → 入力検証画面を開く」から起動できます。通常の筆記画面では検証JSONを記録しません。

## 今回の実装

- Jetpack Ink 1.0.0のInProgressStrokesViewと入力予測による筆圧対応描画。
- Inkの確定筆跡をCanvasStrokeRendererへ同じUIループで引き渡し。
- 筆圧範囲が取得できない場合は、固定幅のマーカーブラシをフォールバックとして使用。
- 黒・青・赤、細・中・太を設定から変更。
- 筆跡のメッシュと消去領域の交差で、接触した筆跡を丸ごと消去。過去サンプルとサンプル間の移動も判定。
- 1回の消しゴム接触を1操作としてUndo/Redo。履歴上限256操作。
- Inkの確定通知が遅れても、筆記・消去の操作順を維持。
- スタイラスとERASER以外は描画しない。別デバイスの指入力とペン入力でpointerIdが同じでも区別。
- 画面回転・検証画面への移動で確定済みの筆跡をViewModelに維持。入力中の未完了の筆跡はキャンセル。
- 横幅は暫定で論理座標1000。画面幅に合わせて表示し、画面外の確定筆跡は描画しない。ズーム・スクロールはPhase 3の対象。

## 下ボタンの一時消しゴム

2026-10-16のユーザー指定で、現在は下ボタンを解放した後もペン先を離すまで消去を維持し、離した時点で元のツールへ戻します。3ボタンの割り当ても総合設定で変更できます。以下の解放時停止はPhase 2当時の検証記録です。

2026-10-15、ユーザーが実機動作を確認し、以下の操作仕様を採用することを確定しました。

`Xiaomi Focus Pen Mouse`デバイスの`KEYCODE_PAGE_DOWN`を使用します。deviceIdは固定しません。別のキーボードや、上ボタン・独立ボタンには機能を割り当てません。

1. ペンを浮かせた状態で下ボタンを押す。
2. 押したままペンを画面につけ、消したい筆跡に触れる。
3. ボタンを解放すると消去を停止する。
4. 次の接触から、画面で選択していたツールへ戻る。

解放時にペンが画面についている場合、その接触中に新しいペン線は描き始めません。長押しリピートは新しい押下として扱いません。フォーカス喪失・アプリの一時停止・デバイス切断／変更で保持状態を解除します。

Phase 1で確認したとおり、接触中に押し始めたボタン操作はこの端末では通知されていません。画面の消しゴム切り替えも利用できます。

## 最初の実機確認（JSON不要）

| 操作 | 確認すること | 実機結果 |
| --- | --- | --- |
| 小さい字・ゆっくりした曲線・速い線を描く | 遅れ、線の欠け、ペンを離した際のちらつき | 未確認 |
| 強弱を付けて描き、色・太さを変更 | 筆圧が反映され、既存の線の設定は変わらない | 未確認 |
| 画面の消しゴムで複数の線を一度になぞる | 触れた筆跡全体が消え、1回のUndoでまとめて戻る | 未確認 |
| Undo→Redo、Undoの後に新しい線を描く | 復元と順序が正しく、新しい編集後は古いRedoが使えない | 未確認 |
| 下ボタンを先に保持して消し、解放後にペンを接触させる | 一時消しゴムとペンへの復帰 | ユーザー実機確認済み。解放で消去停止、同じ接触では描画せず、離して再接触すると復帰する動作を採用 |
| 手のひらを置いて描く／画面回転／入力検証画面から戻る | 誤線・筆跡崩れ・確定済み筆跡の欠落がない | 未確認 |

描画中やInkの確定待ちでは、Undo/Redoと設定変更を無効にしています。見た目の遅延・描画方式の適性は実機で判断します。開発PCのビルド成功だけで実機完了とはしません。
