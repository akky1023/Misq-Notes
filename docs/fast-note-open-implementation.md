# ノートの開閉経路の修正

この文書は2026-11-04時点の既存形式の改善記録。2026-11-05に追加した新形式と移行処理は[新形式の実装記録](storage-format3.md)を参照。

[保存・読み込み方針](fast-note-open-storage-design.md)に基づく、既存形式での開閉経路の改善。

## 実装した動作

- 初期表示後の先読みは表示範囲の上下およそ1画面までとし、遠方の未読パックがあっても終了する。
- スクロール時は先読みを中断して表示先を優先し、閉じる・切り替える際は表示先の読み込みも中断する。
- パック内のレコード読み込みと筆跡の形状生成の間に中断確認を入れ、追加読み込みの形状生成はリポジトリのロック外で行う。
- 検証済みの索引を最大2ノート、各20,000筆跡以下の範囲で再利用する。本文は読み出すたびに従来のチェックサムを検証する。
- 外部本文をまだ持たない部分編集は、端末内の `.partial-<UUID>` に本文・全参照・位置を耐久保存し、未読本文の取得は外部保存のワーカーへ渡す。
- 一覧と再オープンは未送信の記録を優先する。未読の参照を保持し、削除・置換された元の筆跡は読み込み対象に戻さない。
- 外部保存のための全文取得中は端末内保存のロックを保持しない。取得中に編集世代が変わった場合は古い結果を破棄し、最新の記録から再試行する。
- 閉じる処理は端末内保存を確認し、プレビューの完成と保存済み作業ファイルの整理を待たずに一覧へ戻る。

## まだ実装していない範囲

これは設計全体を実装した新保存形式ではない。外部の正本は従来どおりで、外部保存・同期・マージには全文MISQ0002の取得、組み立て、スナップショットが残る。外部保存のスナップショットや索引生成に残る全量処理も、今回すべてをロック外へ移したわけではない。

端末内の記録も全参照を持つため、差分だけの小さなログへの置き換えではない。再オープンでは記録に保存された筆跡を復元し、起動時の未送信記録の復旧は従来の全文復旧を使う。

本文を通常保存・位置別読み込み・同期で共有する不変パック、分割した位置索引、確定状態の親子関係、祖先全文を必要としないメタデータ統合、独立バックアップの復元確認は未実装。[設計レビュー](storage-architecture-review-20261104.md)の移行条件を満たす別領域の新形式が必要になる。共有先での物理回収は追加していない。

## 回帰確認

- 近傍に未読本文がなければ遠方のパックを開かないこと。
- 未送信記録の参照・削除・筆跡の順序を、本文の取得前にも読み出せること。
- 未送信記録の削除・置換が、古い位置別パックより優先されること。
- 外部本文の取得失敗後も記録を保持し、再起動で未読本文と合わせて復旧できること。
- 外部本文の取得を停止しても次の編集を耐久保存でき、古い取得結果で削除済みの筆跡を復活させないこと。
- エディターの近傍先読み、Undo/Redo、全文書き出し、閉じる・切り替える動作。

検証結果：単体テスト328件中326件成功・2件スキップ、外部保存の実機回帰18件成功、通常操作とプレビューの実機回帰6件成功。検証APK・実機テストAPKのビルド成功。release lintは0 errors・12 warnings。

実機は `7b42a7e6` を使用し、検証アプリだけを更新した。外部保存の試験は使い捨てDocumentsProviderとノートコピーで実施し、本番アプリと実ノートは更新していない。実ノートを用いた新旧方式の速度・容量比較と、設計全体の新保存形式の検証は未実施。
